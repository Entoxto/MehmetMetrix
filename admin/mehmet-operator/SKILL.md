# Mehmet Operator

## Назначение

Использовать этот навык как единый вход в административные задачи проекта.
Сначала находить действующий источник правил, затем выполнять минимальное
проверяемое действие. Не дублировать доменные правила внутри этого файла.

Текущий контур содержит только навигацию. Не предполагать наличие локальных
инструментов автоматизации, пока они явно не добавлены и не описаны.

## Порядок работы

1. Прочитать корневой `AGENTS.md`.
2. Прочитать `references/project-map.md` и выбрать источники для задачи.
3. Для добавления, переноса, изменения позиции, размеров, срока доставки или
   другой повторяемой команды прочитать `references/workflows.md`.
4. Перед работой с внешним сервисом загрузить применимый навык коннектора.
5. Преобразовать пользовательскую команду в явный план: действие, объект,
   целевые поля, ожидаемый результат и способ проверки.
6. Перед записью прочитать актуальное состояние точного файла, листа и
   диапазона. Учитывать параллельные изменения пользователя.
7. Выполнить только разрешённые изменения и повторно прочитать результат.
8. Запустить применимые проверки проекта и кратко перечислить изменённые
   объекты, диапазоны и файлы.

## Голосовые команды

- Сохранять смысл команды, а не её разговорную форму.
- Уточнять только отсутствие данных, которое материально меняет результат.
- Не выводить удаление, финансовое действие, публикацию или массовое изменение
  из неоднозначной формулировки.
- Считать изменения Google Sheets черновиком. Публиковать данные приложения
  только после отдельного явного подтверждения по протоколу из
  `references/workflows.md`.
- Проверять, не была ли повторная голосовая команда уже выполнена.

## Ресурсы

- Читать `references/project-map.md` для маршрутизации по проекту.
- Читать `references/workflows.md` для подтверждённых операторских сценариев и
  значений по умолчанию.
- Хранить будущие детерминированные помощники в `scripts/`.
- Не добавлять инструмент без описания его входов, побочных эффектов и
  проверки результата.

## Расширение контура

Добавлять новые правила только после подтверждения на реальном примере.
Ссылаться на существующий источник правды вместо копирования его текста.
Выносить крупные независимые темы в отдельные файлы `references/` и подключать
их напрямую из этого файла.
