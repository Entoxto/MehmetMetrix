# Явная публикация данных

## Модель

Google Sheets остаётся рабочим черновиком. Приложение не опрашивает таблицу и
не запускает публикацию по таймеру: новый снимок появляется только после
отдельной команды пользователя.

Публикуется один согласованный пакет:

- `data/shipments.json`;
- `data/products.json`;
- `data/meta.json`;
- ручной `data/money.json`.

Лист Google Sheets «Оплаты» этот процесс не читает и не изменяет. Финансовые
ручные строки по-прежнему редактируются в `data/money.json`.

## Что происходит по команде

`npm run publish:data` выполняет один канонический сценарий:

1. заново скачивает актуальную Google Sheet;
2. преобразует XLSX в generated JSON;
3. проверяет generated JSON, ручной `money.json` и локальные фотографии;
4. собирает пакет с SHA-256 и уникальной версией;
5. отправляет пакет в защищённый `/api/publish-data` текущего сайта;
6. сервер проверяет схему, хеш и наличие всех указанных фотографий в уже
   развёрнутом сайте; сетевые проверки выполняются ограниченным пулом, чтобы не
   исчерпывать соединения serverless-функции;
7. записывает неизменяемую копию `versions/<version>` в Netlify Blobs;
8. условной атомарной записью заменяет `current` и повторно читает его для
   проверки;
9. локальный скрипт проверяет `/api/data-version`.

Если любой шаг завершается ошибкой, `current` не заменяется и приложение
продолжает показывать предыдущую исправную версию. Версионированные снимки
остаются в Netlify Blobs и позволяют восстановить прежние данные.

## Первичная настройка

Нужен один обычный deploy кода, добавляющий runtime и API публикации. В Netlify
создать секретную переменную:

```text
MEHMET_PUBLISH_TOKEN=<длинная случайная строка>
```

На машине оператора или Hermes создать игнорируемый Git-файл
`.env.publish.local`:

```text
MEHMET_SITE_URL=https://eloquent-buttercream-3d732d.netlify.app
MEHMET_PUBLISH_TOKEN=<та же строка>
```

Production-сайт: `eloquent-buttercream-3d732d`, ветка deploy — `main`.
Netlify Project ID: `facb4a96-e9fc-4a07-951c-a49330c2e339`.

Секрет нельзя коммитить. Вместо файла переменные можно передать обычным
окружением процесса. Для принудительного выбора источника runtime доступны:

- `MEHMET_DATA_SOURCE=local` — всегда использовать JSON текущей сборки;
- `MEHMET_DATA_SOURCE=netlify-blobs` — читать Blobs, в том числе вне Netlify;
- `MEHMET_DATA_STORE` — переопределить стандартный store
  `mehmet-metrics-data`.

Для внешнего чтения Blobs при локальной диагностике дополнительно нужны
`NETLIFY_SITE_ID` и `NETLIFY_AUTH_TOKEN`; обычная публикация через API в них не
нуждается.

## Команды

```bash
# Проверить текущие локальные JSON и собрать пакет, ничего не публикуя
npm run publish:data:dry-run

# Скачать свежую таблицу, проверить и опубликовать
npm run publish:data
```

На Windows `Опубликовать данные.bat` является тонкой оболочкой над той же
командой. Hermes должен запускать именно `npm run publish:data` после явного
подтверждения пользователя, а не повторять логику собственными командами.
Скрипт использует `MEHMET_PYTHON`, если переменная задана; иначе предпочитает
bundled Python Codex и проверяет наличие `pandas` и `openpyxl` до парсинга.

## Runtime приложения

`lib/dataSource.ts` выполняется только на сервере. На Netlify он читает ключ
`current` со строгой согласованностью при каждом запросе к Work, Catalog,
Money или карточке товара. Поэтому пересборка и ручной сброс кэша для обычных
табличных изменений не нужны.

Если Blobs временно недоступен или первая версия ещё не опубликована,
приложение использует JSON-снимок, встроенный в последний deploy. Корневое меню
остаётся статическим; только маршруты, зависящие от данных, рендерятся на
сервере по запросу.

## Фотографии

Фотографии пока не входят в Blobs-пакет. Их источник —
`public/images/products/jpg/`, а изменение требует Git push и Netlify deploy.
Публикацию данных с новым `photo`, которого ещё нет в текущем deploy, сервер
отклонит до переключения `current`.

Безопасный порядок:

1. добавить/переименовать JPG и производные WebP;
2. выполнить `npm run preflight`;
3. отправить код и фотографии в deployment branch и дождаться deploy;
4. выполнить явную публикацию данных.
