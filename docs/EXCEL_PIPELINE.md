# Excel → JSON pipeline

## Источник и результат

Источник правды для поставок, статусов, размеров, материалов и актуальных цен —
Excel / Google Sheet, лист «Поставки».

Пайплайн создаёт:

- `data/shipments.json`;
- `data/products.json`;
- `data/meta.json`.

`data/money.json` не генерируется и валидируется отдельно как ручной источник.

## Точки входа

| Команда | Назначение |
| --- | --- |
| `python Excel/fetch_google_sheet.py` | Скачать актуальный XLSX |
| `python Excel/parse_excel.py --auto` | Распарсить Excel, обновить каталог, проверить и записать JSON |
| `python Excel/update_prices.py` | Повторно синхронизировать price/cost каталога из существующих поставок |
| `python Excel/validate_generated_data.py` | Проверить generated JSON и `money.json` |
| `python Excel/test_parser_logic.py` | Запустить регрессионные тесты парсера |

Windows-сценарий `Запустить с обновлением.bat` выполняет fetch → parse → WebP →
fast preflight → dev server.

## Модули

- `parse_excel.py` — оркестратор полного импорта;
- `excel_parser.py` — чтение листа и построение поставок;
- `parser_utils.py` — разбор названий, размеров, материалов, категорий и фото;
- `catalog_pricing.py` — выбор последних price/cost;
- `data_validator.py` — проверка структуры и доменных инвариантов;
- `json_storage.py` — чтение и атомарная запись JSON;
- `fetch_google_sheet.py` — загрузка XLSX;
- `update_prices.py` — ремонтная актуализация цен;
- `validate_generated_data.py` — standalone-валидация;
- `test_parser_logic.py` — Python-регрессии.

## Используемые колонки

| Колонка | Значение | Результат |
| --- | --- | --- |
| A | № поставки / разделитель года | `shipment.id`, границы поставки, `year` |
| C | Наименование | товар, цвет, размеры или общее количество `(N шт.)` |
| D | Состав | `product.materials` |
| E | Статус позиции | `rawItem.status` |
| F | Статус поставки | `shipment.status` |
| G | Вычисленное количество | проверка результата C; legacy `quantityOverride` |
| H | Цена за единицу, $ | `rawItem.price` |
| I | Итоговая стоимость, $ | вычисляемый контроль `G × H`; не импортируется |
| J | Курс списания | guard для себестоимости |
| K | Себестоимость единицы без карго, ₽ | вычисляется внутри границ поставки; не импортируется |
| L | Итоговая себестоимость без карго, ₽ | вычисляемый контроль `K × G`; не импортируется |
| M | Карго, ₽ | общая сумма карго для блока позиций внутри поставки |
| N | Себестоимость единицы с учётом карго, ₽ | `rawItem.cost`, только при положительном J |
| O | Итоговая себестоимость с учётом карго, ₽ | вычисляемый контроль `N × G`; не импортируется |
| P | Дата поступления | `receivedDate` или `eta` |
| Q | Всего оплачено | вычисляемая сумма O текущей поставки; не импортируется |

Остальные колонки не должны неявно становиться источником новых полей без
изменения валидатора, тестов и документации.

## Границы поставок и годы

- строка с годом в колонке A и без содержательной позиции задаёт текущий год;
- строка с номером поставки и наименованием начинает новую поставку;
- следующие строки с наименованием и без нового номера относятся к текущей
  поставке;
- новый номер, новый разделитель года или конец данных закрывает поставку;
- разделитель года не попадает в `rawItems`.

## Наименования и productId

Размеры читаются из последней пары скобок в наименовании. Имя товара очищается
от размерного суффикса и сопоставляется с каталогом.

Канонический порядок смысловых частей:
`Изделие [модель / крой / стиль] из материала — цвет`. Именная модель и
описания конструкции (`Аляска`, `Агнес`, `в стиле 80-х`, `по новым лекалам`)
ставятся до оборота `из материала`. Имя исходного JPG/JPEG должно в точности
совпадать с очищенным именем товара.

- существующий товар сохраняет свой `productId`;
- новый товар получает стабильный id вида `auto-NNN`;
- `excelRows` хранит все строки источника для диагностики;
- каталог после полного парсинга содержит только товары из текущего источника.

## Состав и смысловая проверка C ↔ D

Колонка C содержит товарное наименование и может описывать внешний вид или
обработку материала. Колонка D фиксирует фактический состав изделия. Поэтому
названия материала в C и D нельзя проверять только буквальным совпадением.

Подтверждённое исключение: формулировка `из кожи страуса` в C может сочетаться
с `100% Кожа барана` в D. В этой модели используется кожа барана с обработкой
под страуса, а не натуральная кожа страуса. Такое сочетание корректно: не
помечать его как ошибку и не заменять состав автоматически.

Это исключение не разрешает произвольные несовпадения. При новой комбинации,
которой нет среди подтверждённых правил, выводить её на проверку как возможную
аномалию, а не как установленную ошибку.

## Размеры и количество

Канонические ключи raw data:

```text
xs, s, m, l, xl, OneSize
```

Неизвестный или повторно указанный размер — ошибка.

Правила количества:

1. Суффикс `(N шт.)` в C задаёт положительное целое общее количество без
   размерной сетки. Парсер создаёт `sizesUnknown: true` и
   `quantityOverride: N`; вычисленное значение G обязано совпасть.
2. Для обычной размерной сетки количество равно сумме размеров.
3. Если нет ни размеров, ни `(N шт.)`, существующая позиция означает `1` вещь.

Колонка G является вычисляемой: формула извлекает числа из последней скобки C,
суммирует размеры либо читает `(N шт.)`, а при отсутствии чисел возвращает `1`.
Не заменяйте её ручным числом. Старый маркер `(на уточнении)` с ручным G
поддерживается только для чтения старых данных.

`(N шт.)` нельзя смешивать с размерами; нулевые, отрицательные и дробные
количества запрещены. `sample` — маркер, а не принудительное количество `1`.

## Категории

Допустимы только:

- `Мех`;
- `Замша`;
- `Кожа`;
- `Экзотика`.

Приоритет определения: Экзотика → Кожа → Мех → Замша. Неизвестная категория
останавливает импорт; fallback `Прочее` запрещён.

## Цена и себестоимость

- историческая цена хранится в позиции поставки;
- каталог получает последнюю доступную price/cost по хронологии поставок;
- при добавлении повторной позиции без явно заданной цены H копирует цену из
  ближайшей предыдущей строки с тем же очищенным наименованием C; очищение
  удаляет только последние скобки размеров или количества и нормализует пробелы;
- явно указанная новая цена имеет приоритет, а исторические строки не
  переписываются; если предыдущей цены нет, цену не угадывать и запросить её;
- I является вычисляемой колонкой: `=IF(OR(Hn="";Hn=0);"";Gn*Hn)`. Формула
  должна присутствовать в каждой строке позиции, даже пока цена не известна;
- пустая или нулевая H означает, что цена пока не задана: I остаётся пустой, а
  парсер не создаёт `rawItem.price`;
- K является вычисляемой колонкой и должна содержать формулу в каждой строке
  позиции. Формула находит начало текущей поставки по последней заполненной A
  на строке с C и ищет курс только от этой строки до текущей. Последнее явно
  введённое значение или формула в J является маркером курса; формула J,
  возвращающая пустоту, останавливает наследование предыдущего курса;
- при пустом, нулевом или отрицательном курсе либо при пустой/нулевой H значение
  K остаётся пустым. Нулевые заглушки в J между поставками не нужны;
- L является вычисляемой колонкой в каждой строке позиции:
  `=IF(OR(Kn="";Kn=0);"";Kn*Gn)`. Пока K недоступна, L остаётся пустой;
- объединённая ячейка J действует на покрываемые ею строки, но её курс никогда
  не переносится через границу новой поставки;
- положительное значение M задаёт общую сумму карго для текущего блока позиций.
  Блок начинается в строке явного значения M и заканчивается перед следующим
  явным маркером M либо на границе поставки. Вертикально объединённая M означает
  один блок на все покрытые строки;
- N является вычисляемой колонкой в каждой строке позиции и считает
  `ROUND(K + M / сумма G текущего блока; 0)`. Одинаковые суммы M в разных
  блоках считаются независимо и никогда не объединяются по самому числу;
- O является вычисляемой колонкой в каждой строке позиции:
  `=IF(OR(Nn="";Nn=0);"";Nn*Gn)`;
- пустой, нулевой или отрицательный M оставляет N и O пустыми. Карго не
  наследуется из предыдущей поставки, поэтому нулевые заглушки в M не нужны;
- значение N импортируется как `cost` только при положительном курсе J. Пустой,
  нулевой или отрицательный J означает неизвестную себестоимость и не обновляет
  стоимость каталога;
- Q содержит формулу только в первой строке каждой поставки. Она находит
  следующую строку поставки по заполненной A на строке с C и суммирует числовые
  значения O до этой границы. Для поставки без рассчитанных O результат пустой;
  ручные диапазоны `SUM(Ox:Oy)` не используются.

## Дата поступления и ETA

Колонка P намеренно допускает два типа значений:

- дата означает фактическое поступление продукции;
- свободный текст означает ожидаемый срок или пояснение по доставке и
  сохраняется как `eta` для показа в приложении.

Если в строках одной поставки указано несколько дат, парсер выбирает самую
позднюю. Если присутствует хотя бы одно текстовое значение, первый очищенный
текст получает приоритет и сохраняется как ETA вместо даты поступления.

## Статусы и оплата

Текст статуса сохраняется из Excel без замены на enum.

На стороне TypeScript `isPaidStatus()` считает статус оплаченным, только если
есть положительная формулировка «оплачен» и отсутствуют отрицания или частичная
оплата. Пустой статус позиции наследует статус поставки.

`paidPreviously` и `noPayment` делают позицию неплатёжной через `isPayable`.
Ручные исключения не следует прятать в статусный текст.

## Фото

Фото опционально. Поле `photo` создаётся только при точном JPG/JPEG в
`public/images/products/jpg/`.

- отсутствие `photo` валидно и показывает `__photo_pending`;
- заданный путь к отсутствующему файлу — ошибка;
- `scripts/convert_to_webp.py` создаёт полноразмерный `webp/` и уменьшенный
  `webp/card/`, обновляет изменённые варианты и рекурсивно удаляет производные
  `.webp`, для которых больше нет JPG/JPEG;
- `npm run validate:images` проверяет ссылки, JPG, оба WebP-варианта и лишние
  файлы.

Папка `jpg/` является источником правды. Полный update-flow сначала пересобирает
`products.json` из Excel и актуального списка JPG, а затем синхронизирует WebP.
Поэтому для удаления фото достаточно удалить исходник и запустить
«Запустить с обновлением».

## Безопасная запись

Полный импорт сначала собирает данные в памяти, затем:

1. актуализирует каталог;
2. проверяет shipments/products/meta;
3. при успехе атомарно заменяет JSON.

Ошибка парсинга или валидации не должна оставлять частично обновлённый набор
generated data.
