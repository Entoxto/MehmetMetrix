# Инструкция по работе с данными

## Структура данных

- `products.json` — каталог изделий; генерируется из Excel и перезаписывается при парсинге
- `shipments.json` — партии с историческими ценами; генерируется из Excel и считается основным источником цен/статусов
- `money.json` — ручные финансовые строки, подписи, депозиты и ручные доплаты в `Всего к оплате`
- `meta.json` — метаданные обновления данных (время последнего парсинга); используются в нижнем блоке интерфейса как дата последнего обновления

Все четыре файла входят в единый публикуемый пакет. В production приложение
читает последнюю явно опубликованную версию из Netlify Blobs; файлы в этой
папке остаются входом публикации и резервным снимком последнего deploy.

## Что является источником правды

- Для поставок, статусов, размеров, материалов и цен источником правды является Excel / Google Sheet.
- `products.json`, `shipments.json` и `meta.json` не стоит редактировать вручную как постоянное решение: их перезапишет следующий парсинг.
- `money.json` можно редактировать вручную, это не автогенерируемый файл.
- В `money.json`:
  - `deposits` — ручные строки для блока `Депозитов внесено`
  - `pendingManual` — ручные дополнительные строки для блока `Всего к оплате`
- `money.json` проверяется командой `npm run validate:data`: `amount` должен быть положительным числом, а строки `title` / `lines` — непустыми.
- Лист Google Sheets «Оплаты» не является источником `money.json` и не
  изменяется конвейером публикации.
- `npm run publish:data` всегда отправляет generated JSON и `money.json`
  вместе; частично обновить только один runtime-файл нельзя.
- Если нужно быстро проверить гипотезу локально, ручная правка `products.json` или `shipments.json` допустима только как временный обходной путь.

## Архитектура цен

**Цены хранятся в партиях**, а не в каталоге. Это позволяет:
- Сохранять историческую правду (партия 1 = $100, партия 2 = $110)
- Автоматически обновлять каталог — берётся цена из последней партии
- Себестоимость (`cost`) берётся из колонки N Excel только если курс списания в
  колонке J положительный. Вертикально объединённая ячейка J задаёт курс для
  всех покрытых ею строк. Пустой, нулевой или отрицательный J означает, что
  итоговая себестоимость неизвестна и не обновляет последнюю стоимость каталога.

При добавлении повторной позиции без явно названной цены колонка H получает
цену из ближайшей предыдущей строки той же модели. Совпадение определяется по
полному наименованию в C без последних скобок с размерами или количеством.
Явно указанная новая цена имеет приоритет: подорожание допустимо, а старые
поставки не переписываются. Если совпадения нет и цена не названа, цену нельзя
угадывать — H остаётся пустой до уточнения.

Колонка I всегда содержит формулу `G × H`. При пустой или нулевой H результат
остаётся пустым, но формула из I не удаляется.

Колонки K и L также всегда остаются формульными. K считает себестоимость одной
единицы без карго по цене H и последнему явно заданному курсу J только внутри
текущей поставки. Формула в J считается новым маркером курса, даже если пока
возвращает пустоту. При неизвестном, нулевом или отрицательном курсе K остаётся
пустой; L считается как `K × G` и в этом случае тоже остаётся пустой. Нули в J
не используются как разделители поставок: границу задаёт номер поставки в A.

Колонки N и O тоже всегда остаются формульными. Положительное значение M задаёт
общую сумму карго для блока внутри текущей поставки; новый явный M начинает
следующий блок. N рассчитывает себестоимость единицы как
`ROUND(K + M / сумма G блока; 0)`, O — как `N × G`. Одинаковые суммы карго в
разных блоках считаются независимо. Если M не задана или не положительна, N и O
остаются пустыми; нулевые разделители между поставками в M не используются.
Карго можно внести до появления курса: пока J не содержит положительного курса
и K не рассчитана, N, O и итог поставки Q остаются пустыми.

Колонка P хранит либо фактическую дату получения, либо свободный текст ETA,
который приложение показывает пользователю. Из нескольких дат поставки парсер
выбирает последнюю; текстовый прогноз имеет приоритет над датами. Колонка Q не
является отдельным источником данных: одинаковая формула в первой строке каждой
поставки автоматически суммирует O до следующей границы A и остаётся пустой,
пока в O нет рассчитанных значений.

## Как добавить новый товар в каталог

**Вариант 1 (рекомендуется):** добавьте строку в таблицу Excel (лист «Поставки») и запустите парсинг («Запустить с обновлением»). Товар появится в каталоге с id вида `auto-NNN`; `materials` подтягиваются из колонки `Состав`, а `excelRows` хранит номера всех строк этой модели. Если подходящего JPG ещё нет, поле `photo` не создаётся и приложение показывает общую заглушку.

**Вариант 2:** откройте `data/products.json` и добавьте объект в массив `products` (файл перезаписывается при каждом парсинге из Excel). Поле `price` не указывается — цена берётся из партий автоматически.

## Формат наименований

Все названия следуют формату:
**`Изделие [модель / крой / стиль] из материала — цвет`**.

Именная модель, конструкция и стилевое уточнение ставятся сразу после типа
изделия, до оборота `из материала`. Это сохраняет один порядок для `Аляска`,
`Агнес`, `в стиле 80-х`, `по новым лекалам` и других будущих уточнений.

Примеры:
- `Дублёнка Аляска из меха астроган — антрацит`
- `Жакет в стиле 80-х из кожи Hermes — mouse`
- `Куртка по новым лекалам из кожи питона — белый`
- `Жакет приталенный из кожи питона — чёрный глянцевый`
- `Брюки из замши — коричневый`
- `Дублёнка из мериноса — бежевый`

В закрытых карточках Work последняя часть после разделителя визуально
показывается как цвет: на desktop — отдельной колонкой, на mobile — второй
строкой под названием модели. Это только представление; строка в Excel и
сгенерированных JSON остаётся исходной и не разбивается на новые поля.

Если в названии есть дополнительные скобки, размеры всё равно берутся из последней скобки:
`Куртка (капсула) из кожи — чёрная (XS-1, S-2)` → `xs: 1`, `s: 2`.

Если общее количество известно, а размерная сетка ещё нет, укажите количество
прямо в последней скобке колонки C: `Куртка из кожи — коричневая (10 шт.)`.
Формула в G автоматически вернёт `10`, а парсер создаст `sizesUnknown: true` и
`quantityOverride: 10`. Такая позиция показывается в Work с меткой «Размеры на
уточнении» и не добавляет фиктивный размер в каталог.

Количество без размеров нельзя смешивать с размерной сеткой: запись
`(XS-2, 10 шт.)` является ошибкой. Значение должно быть положительным целым
числом. Если нет ни размеров, ни явного количества, существующая позиция
считается одной вещью. Старый вариант `(на уточнении)` + ручное значение G
поддерживается только для обратной совместимости; для новых строк используйте
`(N шт.)` и не заменяйте формулу G ручным числом.

Если возможность выпуска позиции ещё не подтверждена, добавьте независимый
маркер `под вопросом` в последние скобки C. Допустимые примеры:
`(образец XS-1, под вопросом)`, `(10 шт., под вопросом)` и
`(под вопросом)`. Парсер создаёт `underQuestion: true`, а Work показывает
плашку «Под вопросом». Маркер не меняет количество, статус, платёжность,
каталожное имя или признак образца.

## Как временно вручную поправить партию

Правильный рабочий путь — менять Excel / Google Sheet и заново запускать парсинг.

Если нужна локальная проверка без немедленного обновления Excel:

1. Откройте файл `data/shipments.json`
2. Найдите нужную партию и добавьте объект в `rawItems`
3. Помните, что следующий парсинг перезапишет этот файл

```json
{
  "productId": "python-010",
  "overrideName": "Жакет приталенный из кожи питона — красный глянцевый",
  "price": 550,
  "sizes": { "xs": 3, "s": 2 },
  "status": "В производстве 🛠️"
}
```

**Обязательные поля:**
- `productId` — ссылка на товар в каталоге
- `price` — цена на момент партии (историческая)

**Опциональные поля:**
- `overrideName` — название для отображения (если отличается от каталога)
- `sample: true` — пометить как образец
- `underQuestion: true` — показать независимую метку «Под вопросом»
- `quantityOverride: 1` — положительное целое переопределение количества
- `note: "текст"` — примечание
- `paidPreviously: true` — оплачено ранее (не входит в сумму)
- `noPayment: true` — без оплаты (например, вернулось с ремонта)

`sample` — только метка образца. Если размеры или колонка G Excel задают количество больше 1, это количество сохраняется и участвует в сумме поставки.

На экране Work этот же флаг участвует в визуальной классификации поставки:
обычные позиции добавляют плашку `Партия`, позиции с `sample: true` — плашку
`Образец`. Если в поставке есть оба типа позиций, UI показывает обе независимые
плашки; отдельное состояние `С образцом` в данных не хранится и не выводится.

> Статусы в JSON хранятся как текст из Excel. Старые кодовые варианты вроде `in_progress` поддерживаются только как обратная совместимость, но для новых данных их использовать не нужно. Финансовый расчёт использует статус позиции; если он пуст, позиция наследует статус своей поставки.

> Ключи размеров в `rawItems.sizes` должны быть каноническими: `xs`, `s`, `m`, `l`, `xl`, `OneSize`. Неизвестный размер теперь считается ошибкой данных, а не превращается в `S`.

> Размер нельзя указывать дважды в одной скобке, например `(XS-2, XS-3)`: парсер остановится и укажет номер строки Excel. Исправьте таблицу до повторного запуска.

## Как добавить фото

1. Поместите фото в папку `public/images/products/jpg/`
2. Назовите файл ТОЧНО как название товара с вариантом:
   - Пример: `Жакет приталенный из кожи питона — чёрный глянцевый.jpg`
3. Рекомендуемый формат: JPG
4. Рекомендуемый размер: 1200x1600px или больше
5. Запустите «Запустить с обновлением» или `python Excel/parse_excel.py --auto`: парсер сам добавит `photo`, если файл найден.
6. Запустите `python scripts/convert_to_webp.py --auto`: скрипт создаст
   полноразмерный `webp/<имя>.webp` для страницы товара и уменьшенный
   `webp/card/<имя>.webp` для карточек. Карточный вариант автоматически
   вписывается целиком в квадрат; цвет полей берётся из углов исходной
   фотографии. Изменённые исходники пересобираются, а WebP без соответствующего
   JPG/JPEG автоматически удаляются рекурсивно.

Фото не обязательно добавлять сразу. Без него модель остаётся валидной, а каталог показывает `__photo_pending`. При каждом запуске `npm run validate:images` выводится количество моделей без фото и список с номерами строк Excel. Для существующего `photo` карточный WebP обязателен; отсутствие полноразмерного WebP остаётся предупреждением, потому что UI умеет перейти на исходный JPG.

`public/images/products/jpg/` — единственный ручной источник изображений.
Содержимое `webp/` и `webp/card/` является generated-слоем: не поддерживайте эти
копии вручную. При удалении или переименовании JPG сначала обновите данные
парсером, затем запустите конвертер; сценарий «Запустить с обновлением» делает
оба шага в правильном порядке.

Не добавляйте поля и не подгоняйте пропорции исходника вручную: каталог
показывает квадратный generated-вариант через `object-fit: contain`, поэтому
детали изделия сохраняются и на телефоне, и на desktop.

Детальная страница использует полноразмерный WebP и тоже показывает исходник
целиком. На desktop рамка фотографии повторяет его пропорции; заранее вручную
масштабировать или обрезать JPG/JPEG для этого экрана не нужно.

## Категории

Доступные категории:
- `Мех` — меринос, пони, кёрли, таскана
- `Замша` — замшевые изделия
- `Кожа` — кожа Hermes и др.
- `Экзотика` — питон и др. экзотические материалы

Каталог `data/products.json` при каждом парсинге **собирается заново** из Excel: в нём остаются только товары, встретившиеся в текущем файле. Категория выводится по названию (по корням): приоритет **Экзотика** (питон) > Кожа > Мех > Замша. Так «кожи питона» даёт Экзотику. Если ни один корень не найден, парсер считает это ошибкой и останавливается: категории `Прочее` в пайплайне быть не должно. **Размеры** (поле `sizes`) заполняются автоматически: объединение всех размеров, которые встречаются у этого товара в позициях поставок (из тех же данных, что уже есть в партиях); порядок — xs, s, m, l, xl, onesize. **Материалы** (поле `materials`) автоматически подтягиваются из колонки `Состав` в Excel: первая содержательная строка идёт в `outer`, строка с `Подкладка` — в `lining`, остальное сохраняется в `comments`. **Строки Excel** сохраняются в `excelRows`, а **photo** добавляется только при наличии точного файла в `public/images/products/jpg/`.
